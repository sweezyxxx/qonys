# Team responsibilities

## Confirmed analysis and coordination role

Confirmed role: **Temirlan Almukhamedov — Systems Analyst and Technical Coordinator** (DEC-55).

The stakeholder approved the named role and its responsibilities. This describes engineering and coordination ownership rather than a claim that all listed work has already been completed.

### Responsibility statement

Responsible for requirements elicitation and specification, user scenarios and acceptance criteria, solution and data modelling, database schema design in collaboration with the backend developer, architectural documentation, repository workflow, development environment configuration, project documentation, task traceability and coordination of verification activities.

### Expected engineering deliverables

| Responsibility | Reviewable deliverables | Collaboration |
| --- | --- | --- |
| Requirements engineering | Scope, functional and non-functional requirements, acceptance criteria and change decisions | Validate needs with users; review feasibility with both developers. |
| System and interaction modelling | Context, use case and component diagrams; scenario and interface definitions | Review screen flows with frontend and component boundaries with backend. |
| Data modelling and database design | ER model, entity definitions, constraints and integrity rules | Agree physical schema and migration implementation with backend. |
| Repository and environment coordination | Repository structure, contribution workflow, configuration examples and agreed environment setup | Each member contributes through an individual account; runtime setup is reviewed with developers. |
| Documentation and traceability | Versioned documentation, decision records and requirement-task-deliverable links | Keep Notion, the repository and real YouTrack tasks consistent. |
| Verification planning | Test scenarios, evaluation protocol, evidence collection and acceptance reviews | Developers implement component tests; all members participate in system validation. |

The final report should distinguish planned responsibilities, authored deliverables and individually demonstrated contributions. A role label does not replace that evidence.

## Reference for role framing

The [IIBA Business Analysis Standard task overview](https://www.iiba.org/knowledgehub/business-analysis-standard/4-tasks-and-knowledge-areas/introducing-business-analysis-tasks/) covers stakeholder elicitation, requirements lifecycle management, specification and modelling of requirements/designs, verification, validation and solution evaluation. The proposed QONYS role combines that analysis work with the specific repository, environment and coordination responsibilities described by the stakeholder; the combined title is a project recommendation, not a formal title mandated by the standard.
